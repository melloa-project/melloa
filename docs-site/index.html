Melloa / Melli

A private home for Melli.

Melloa is the owner-controlled system. Melli is the persistent AI partner whose memory, context, and relationship should survive model and provider changes.

Current deployment status: not ready for first owner deployment.
Read the source status First-server guide

Current target

The first real deployment is a dedicated server, not a demo site.

Dedicated Debian server

The qualification path is a low-maintenance home-server install with restart, reboot, backup, recovery, update, and rollback evidence.

Telegram owner chat

The normal owner interface is a private one-to-one Telegram bot chat, paired to the exact owner and backed by canonical conversation continuity.

Hosted model routes

The first path assumes hosted OpenAI-compatible providers: one capable route and one cheaper economy route. A local GPU or local model is not required.

Bounded self-change

Codex/self-change is part of readiness only as an owner-approved loop: proposed diff, exact approval token, commit, push, deploy, and rollback evidence.

What this replaces

The old MkDocs architecture site was stale.

Pages that led with preview milestones, local no-network tours, camera plans, ADR lists, provider-routing architecture, or a roadmap are not the current owner setup path. The active project direction is subtractive: one obvious conversation-first deployment path, with infrastructure details kept behind the moments where they affect owner decisions.

Readiness bar

The public answer stays “not ready” until the real server proves it.

  • clean bootstrap and guided first install on the dedicated server;
  • live Telegram conversation through real capable and economy model routes;
  • reboot verification, backup health, encrypted restore drill, update, and rollback;
  • one owner-approved Codex/self-change deployment with retained evidence;
  • dogfooding evidence that Melli is useful as a continuing relationship, not a fixture.
