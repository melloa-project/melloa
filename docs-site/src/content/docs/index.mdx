The current path is intentionally concrete: a dedicated Debian 13 (`trixie`), Ubuntu 24.04 LTS
(`noble`), or Pop!_OS 24.04 (`noble`) amd64 server booted with systemd, a private Telegram bot chat,
two hosted OpenAI-compatible model routes, encrypted backups, and a bounded self-change loop that
can propose, commit, push, deploy, and roll back owner-approved changes.

This site is the public front door. It should help you get a working Melli, then use Melli to improve
the system from there.

## What this is not

Melloa is not starting as a generic multi-agent harness, channel gateway, or plugin marketplace.
Those systems are useful references, but the first deployment is narrower: one owner, one Telegram
chat, hosted model routes, bounded self-change, and recovery evidence. See [Runtime loop](./runtime-loop/)
for the closed-loop design and [Harness comparison](./harnesses/) for the current fork/adopt
decision.

Hermes is the most relevant reference for the later proactive layer: cron, event-triggered work,
skills, memory, and Telegram delivery from an always-on server. Melloa should evaluate that through
one concrete [proactive goal loop](./proactive-goals/) after the base server can recover from
self-change.

## What you need

- a dedicated Debian 13 (`trixie`), Ubuntu 24.04 LTS (`noble`), or Pop!_OS 24.04 (`noble`) amd64
  server booted with systemd that you can administer with `sudo`;
- a Telegram bot token; setup discovers your numeric owner ID during private pairing;
- a capable hosted model endpoint, model ID, bearer token, and reviewed pricing;
- an economy hosted model endpoint, model ID, bearer token, and reviewed pricing;
- an owner-mounted encrypted backup repository and a restic password kept off the server;
- a GitHub token for this repository when enabling the self-change loop;
- a Codex/OpenAI API key for the bounded planner worker.

Start with [Deploy the server](./deploy/).
