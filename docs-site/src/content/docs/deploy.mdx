---
title: Deploy the server
description: The first-owner server setup path for Melloa.
---

This is the setup path to follow on the actual home server. It goes from a clean Debian 13
(`trixie`) amd64 machine booted with systemd to one persistent Telegram conversation with Melli.

## 1. Prepare the machine and clone Melloa

Use a dedicated Debian 13 (`trixie`) amd64 host booted with systemd. Log in with a user that can run
`sudo`, then install the two packages needed to fetch the reviewed source:

```bash
sudo apt-get update
sudo apt-get install --yes --no-install-recommends ca-certificates git
```

Clone Melloa:

```bash
git clone https://github.com/melloa-project/melloa.git
cd melloa
```

## 2. Mount backup storage

Attach storage that is independent from the server root disk. The guided path defaults to
`/mnt/melloa-off-device-backup`. Melloa will not format disks for you, and the setup path will not
accept a plain directory on the server's root disk as a backup repository.

If the storage is already mounted, these checks should pass:

```bash
sudo mkdir -p /mnt/melloa-off-device-backup
findmnt --mountpoint /mnt/melloa-off-device-backup
test "$(stat --format='%d' /mnt/melloa-off-device-backup)" != "$(stat --format='%d' /)"
```

Both checks should succeed. If the second command fails, the backup path is just a directory on the
server disk; mount real off-device storage before continuing.

If `findmnt` prints nothing, inspect the available prepared disks and mount one deliberately:

```bash
lsblk -o NAME,FSTYPE,UUID,SIZE,MOUNTPOINTS
```

For a disk or USB volume that is already formatted for this purpose, prefer a durable `/etc/fstab`
mount by UUID, then run `sudo mount /mnt/melloa-off-device-backup` and repeat the checks above. For
a NAS share, create the equivalent NFS or CIFS mount first, then repeat the same checks. Do not run
`mkfs` from this guide; formatting is destructive and should be a separate owner decision.

## 3. Bootstrap host prerequisites

Run the bootstrap from the Melloa checkout:

```bash
sudo infra/server/bootstrap-debian.sh --source "$PWD" --self-change-tools
```

That installs Docker, Compose, Python, Node.js, uv, Go, and the pinned Codex CLI toolchain used by
the owner-approved self-change workers. Codex is for self-change planning; it is not Melli’s normal
conversation model.

## 4. Create the Guardian public handoff

Create the public-only Guardian status files beside the Melloa checkout:

```bash
cd ..
git clone https://github.com/melloa-project/melloa-guardian.git
cd melloa-guardian
make preview-state
cd ../melloa
```

`make preview-state` prints two paths. Keep them ready for setup:

```text
.../melloa-guardian/state/local-preview/status.json
.../melloa-guardian/state/local-preview/public.pem
```

Only those public files go into Melloa. Guardian private keys, journals, locks, and control commands
stay outside Melloa.

If the Guardian checkout is beside Melloa exactly as shown above, first install detects those two
public files and offers them as the defaults. Press Enter at the Guardian prompts to use them.

## 5. Have these inputs ready

The installer asks for the owner-controlled values. Do not put these into Git.

From the Melloa checkout, you can print the same preparation list without starting setup:

```bash
infra/server/first-install.sh --print-input-checklist
```

That command does not require `sudo`, does not prompt for secrets, and does not install files.

| Input | What to prepare |
| --- | --- |
| Telegram bot token | Create one dedicated BotFather bot for Melli. Do not reuse a bot already connected to another service. |
| Telegram owner ID | Leave blank during guided setup unless you already verified the numeric ID; setup pairs the private chat for you. |
| Capable model route | Usually the `openai` preset, a reviewed model ID, GBP input/output prices, request cost ceiling, and API key. |
| Economy model route | The `openai` preset with a cheaper model, or `external` with a reviewed OpenAI-compatible hosted provider. |
| Backup repository | A mounted absolute path such as `/mnt/melloa-off-device-backup`. |
| Restic password | 32-128 base64url-safe characters retained separately from the server and backup disk. |
| GitHub token | Fine-grained token for this repository with contents read/write. |
| Codex/OpenAI API key | Used by the bounded planner worker, not as Melli’s normal conversation route. |

### Telegram bot

In Telegram, open `@BotFather` and create a dedicated bot:

```text
/newbot
```

Give it a human name such as `Melli`, then a username ending in `bot`. Copy the HTTP API token
BotFather returns. Do not send `/start` to the bot yet; setup will print an exact `/start ...`
pairing phrase later.

Keep this bot out of groups for the first deployment. Setup can clear an existing webhook, but no
other long-polling process should be using the same bot token.

### Hosted model routes

For the simplest hosted model setup, choose `openai` for both routes:

- `capable`: press Enter for the `gpt-5.6-terra` default, or type another reviewed stronger model;
- `economy`: press Enter for the `gpt-5.6-luna` default, or type another reviewed cheaper model;
- enter current input/output prices as GBP decimals per million tokens, without a currency symbol;
- enter a maximum GBP cost per request, also as a decimal;
- enter the API key only when setup asks for the secret.

The `openai` preset fills the OpenAI HTTPS base URL and Responses API style for you. You do not need
to type those fields for the first path.

When you keep the default OpenAI model IDs, setup prints the official OpenAI standard
short-context USD reference prices before asking for GBP values:

| Route | Default model | Official USD reference before GBP conversion |
| --- | --- | --- |
| `capable` | `gpt-5.6-terra` | USD 2.00 input / USD 12.00 output per 1M tokens |
| `economy` | `gpt-5.6-luna` | USD 0.20 input / USD 1.20 output per 1M tokens |

Convert the relevant prices to GBP for your account, region, context length, and service tier.
Setup does not fetch live exchange rates.

Use `external` only when another hosted provider or router gives you all of these facts: HTTPS
OpenAI-compatible base URL, exact model ID, API style (`responses` or `chat_completions`), bearer
token, and input/output prices converted to GBP. A cheaper online frontier-lab provider is fine
when it exposes that shape; if it does not, defer it rather than guessing.

Examples for the OpenAI route are `gpt-5.6-luna` for economy, `gpt-5.6-terra` for balanced capable
work, and `gpt-5.6-sol` for the highest-capability route when your account access and reviewed
pricing justify it. The `openai` setup preset offers `gpt-5.6-luna` as the economy default and
`gpt-5.6-terra` as the capable default; type another reviewed model ID if needed. Setup accepts the
exact model ID you enter and does not require a local model.

Do not enter example or zero prices just to get through setup. Melloa stores these values so
`/status` can report the exact route and cost boundary you approved.

### Self-change credentials

The GitHub token and Codex/OpenAI API key are for the bounded self-change workers. They are separate
from normal conversation routing:

- create a fine-grained GitHub personal access token scoped only to `melloa-project/melloa`;
- set repository access to only this repository;
- set repository permissions to `Contents: Read and write`;
- do not grant admin, workflow, package, organization-wide, or all-repository access for the first
  proof;
- the GitHub token is used only by the applier after exact owner approval;
- the Codex/OpenAI API key is used by the confined planner worker;
- do not paste a ChatGPT/Codex subscription login artifact into setup.

If you need a restic password generator:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Store that output somewhere the server and backup repository cannot both lose.

## 6. Run the guided install

From the repository checkout:

```bash
sudo infra/server/first-install.sh --source "$PWD"
```

Use these choices for the first home-server path:

| Prompt area | Choice |
| --- | --- |
| backup repository | Enter the mounted path, normally `/mnt/melloa-off-device-backup`. |
| Guardian files | Press Enter if setup detected the sibling Guardian checkout, otherwise enter the `status.json` and `public.pem` paths printed by `make preview-state`. |
| Telegram owner ID | Leave blank to pair now. |
| Telegram pairing | Send the exact `/start ...` phrase printed by setup to the bot’s private chat. |
| capable route | Use the stronger hosted model route. |
| economy route | Use the cheaper hosted model route. |
| initialize backup | Answer `yes`. |
| enable bounded self-change | Answer `yes`; this is the default on a real interactive server install. |
| Codex credential mode | Choose `api-key`. |

The installer writes private configuration under `/etc/melloa/private`, activates the runtime,
pairs the exact Telegram owner, and asks you to prove the first Telegram conversation. During final
verification, send the exact setup message printed in the terminal. The verifier checks that the
real Telegram worker accepted the message, got a model reply, and delivered it back to the private
chat.

## 7. First conversation

When setup finishes, stay in the same Telegram chat and send:

```text
/status
```

Then send an ordinary message to Melli. Machine login should become rare after this point; normal
interaction is Telegram.

Also check the route controls from Telegram:

```text
/model
/model economy
/model capable
/think Give me one sentence proving the capable route works.
```

Melloa should report the selected route and exact model destination. It should not silently fall
back from one route to another.

## 8. Prove the server survived setup

After the first conversation works, make one small owner-approved change through the self-change
loop. That proves Melloa can help evolve its own server path instead of leaving you to maintain a
static install by hand.

Use a small public-safe test/docs request. Do not use the first proof to change deployment scripts,
Guardian, Telegram pairing, database roles, migrations, release policy, or self-change policy.

In Telegram:

```text
/change propose Add a focused unit test for one existing owner-visible /change command message.
```

When the proposal is ready, inspect it:

```text
/change
/change diff <change_id>
```

Approve only if the retained diff is exactly acceptable:

```text
/change approve <change_id> <16-character proposal token>
/change show <change_id>
```

The proof is successful when `/change show <change_id>` reports the deployed state and deployed
revision. Then run:

```bash
sudo /usr/local/libexec/melloa/qualification-record
sudo /usr/local/libexec/melloa/verify-owner-journey
```

Read the `next_steps` section in `qualification-record`. It is the local evidence checklist: it
tells you whether backup, Telegram verification, restore drill, self-change, update, and rollback
evidence are present, and gives the next command for anything missing. Run it again after each
proof until every local evidence line is present. Keep `/change show <change_id>` from Telegram as
the self-change proof because that deployed proposal receipt lives in the app conversation state.

Open [Runtime loop](../runtime-loop/) for the closed-loop design and [Self-change loop](../self-change/)
for the safety model.

Then run the two maintenance proofs:

```bash
sudo reboot
```

After the server returns:

```bash
sudo /usr/local/libexec/melloa/verify-owner-journey
sudo /usr/local/libexec/melloa/restore-drill
sudo /usr/local/libexec/melloa/verify-owner-journey
sudo /usr/local/libexec/melloa/qualification-record
```

If `qualification-record` still reports missing update or rollback evidence, wait until a later
reviewed `main` commit exists, then run the installed `update` and `rollback` wrappers from the
repository deployment guide.

## If setup stops

Fix the reported cause and rerun the same command. The guided install is designed to reuse existing
private configuration instead of overwriting it.

Common stops:

- backup path is not a mount: mount off-device storage at the path and rerun;
- Codex CLI is missing: rerun `sudo infra/server/bootstrap-debian.sh --source "$PWD" --self-change-tools`;
- Telegram pairing does not complete: make sure the bot is dedicated to Melli, then send the exact
  `/start ...` phrase to the bot’s private chat;
- model route check fails: verify the base URL, API style, model ID, bearer token, and GBP prices;
- final owner verification cannot be completed immediately: rerun
  `sudo /usr/local/libexec/melloa/verify-owner-journey` when you can send the Telegram phrase.
